# T-16: Crash recovery on startup

## Context

`recoverFromWal(id)` already exists in `src/storage/session.ts` (T-04). When the user kills the process mid-stream (SIGKILL, OOM), the WAL file survives but there's no UI to offer recovery on the next launch.

This ticket wires the WAL scanner into the app startup and shows a `<RecoveryPrompt>` when orphan WAL files are detected.

## Files

**Create:**
- `tests/recovery.test.tsx` — simulate orphan WAL, verify prompt appears

**Modify:**
- `src/storage/session.ts` — export `scanWalFiles()` function (scans session dir for orphan WALs, returns list of session IDs)
- `src/app.tsx` — in the startup effect (useEffect in App component), call `scanWalFiles()`. If orphans found, render `<RecoveryPrompt>` instead of `<Layout>`.
- `src/ui/RecoveryPrompt.tsx` — Ink component showing:
  - Number of orphan sessions
  - First 60 chars of each session (read from WAL's first user message)
  - Options: [Y]es (recover all) / [D]iscard all / [S]kip (dismiss)

## Implementation details

1. `scanWalFiles()` in `src/storage/session.ts`:
   - Reads the sessions directory (from `paths.ts`/config)
   - Lists all `*.wal` files
   - For each WAL, reads the first few bytes to extract the first user message
   - Returns `Array<{ id: string; preview: string }>`
   - Returns empty array if no orphans (normal startup — no recovery UI)

2. `RecoveryPrompt.tsx`:
   - `useInput` for Y/D/S keys
   - Y: for each orphan, calls `recoverFromWal()` to get chunks, reconstructs the assistant message, appends to session messages, deletes WAL
   - D: deletes all orphan WALs, transitions to normal Layout
   - S: dismisses prompt, transitions to normal Layout (WALs remain for next startup)

3. `app.tsx`:
   - In the `App` function component, add a `useEffect` that runs `scanWalFiles()` on mount
   - If orphans detected, set local state `recoveryMode: orphanIds` 
   - When recoveryMode is set, conditionally render `<RecoveryPrompt>` instead of `<Layout>`
   - RecoveryPrompt has an `onDone` callback that clears recoveryMode

4. Tests (`tests/recovery.test.tsx`):
   - Create a mock WAL file in a temp dir
   - Verify scanWalFiles finds it
   - Verify RecoveryPrompt renders with the right text
   - Verify Y recovers, D discards, S skips
